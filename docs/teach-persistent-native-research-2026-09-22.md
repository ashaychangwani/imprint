# Persistent native research checkpoint

**Prepared; provider and fresh-teach validation pending.** Each native research pass
now uses one assignment. Its actions and observations stay with the same running
child through the existing assignment-tools bridge. Master-directed follow-ups
start a new pass on that retained child. This reduces orchestration; it is not a
claim that the entire runtime has become smaller or that teaches now succeed.

An independent review counted 64 research assignments among Flights 17's 76 total
assignments. Even saved-response inspection passed through the routing parent.
The measured retained-follow-up dispatch median was 34.59 seconds. Those waits
overlap; they cannot be summed or claimed as recovered wall time.

The new adapter implements the existing analyzer interface. The action executor,
validation, repair loop, shared-memory exchange, fresh producer calls and exact
proof checks remain unchanged. The parent routes a complete pass once; the child
uses respond/read_context until the host returns completion. Complete paged inputs
and step identities prevent silent truncation and duplicate execution. The final
acknowledgement cannot replace proof. No extra worker scheduler, provider policy,
site-specific strategy or public tool parameter is added.

Inputs, outputs and timestamps remain in private native-research JSONL files.
Native-family usage remains the accounting authority; these protocol actions do
not emit another set of provider token totals. Non-native execution keeps its
existing analyzer and four-worker behavior.
