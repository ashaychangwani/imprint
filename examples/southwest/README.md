## Status: API path is bot-blocked, playbook path is the one to use

`bun src/cli.ts cron southwest --once` with `replayBackend: fetch` returns:

```
[FORBIDDEN] Request 0 returned 403: { "code": 403050700 }
```

Southwest's API sits behind Akamai Bot Manager. The 403 fires regardless
of whether we send the captured `_abck` cookie — Akamai validates a
sensor token bound to live JS execution + TLS fingerprint, neither of
which a Node `fetch` client can satisfy. This is exactly the case the
playbook was built for.

`cron.json` is configured with `replayBackend: "playbook"` so the
polling daemon uses the browser path. To run end-to-end:

```bash
# One-time browser install
bunx playwright install chromium

# Verify the playbook works with --headed (lets you see the form fill out)
bun src/cli.ts playbook southwest --headed \
    --param origin=SJC --param destination=SAN \
    --param depart_date=2026-06-20 --param selected_date=2026-06-23

# Then start the cron
bun src/cli.ts cron southwest
```

## Playbook tuning notes

The first compiled playbook ran 7/12 steps before hitting Southwest's
React-heavy form quirks. The infrastructure issues that surfaced (and
got fixed in the runner) were:

- **Hidden duplicate elements**: Southwest's autocomplete renders both
  a custom dropdown AND a hidden native `<select>` for accessibility.
  The runner now filters to visible elements before picking `.first()`.
- **Wrapper intercepts pointer events**: clickable `<strong>` text is
  wrapped in a styled `role="checkbox"` that intercepts pointer events.
  The runner now retries with `force: true` since click events bubble.
- **Date-picker overlay**: typing into the date input opens a calendar
  popover that covers the trip-type dropdown. Solved by adding a
  `press: Escape` step between the date input and the next click.
- **Dropdown timing**: clicking a trigger that opens a popover needs
  `wait_for: sleep:300+`, NOT `wait_for: visible` (which resolves to
  the trigger itself). The compiler prompt now teaches this pattern.

Beyond step 8, Southwest's form has further quirks (the trip-type
dropdown click doesn't reliably open the listbox in headless mode).
**Run `--headed` for any further tuning** — the screenshot-on-failure
in `/tmp/imprint-playbook-*-stepN-*.png` makes each iteration fast.

## What this directory proves

Even though the full Southwest end-to-end requires hand-tuning the
playbook (a process that took 5 commits to get right for a real-world
React SPA), this directory demonstrates:

1. The **recorder** captures both network *and* DOM events with enough
   fidelity to drive both replay paths from one session.
2. The **shrinker** correctly shrinks an 813-request SPA capture to the
   34 load-bearing requests within token budget.
3. The **redactor's `--keep-header` flag** preserves public app keys
   without sacrificing per-user secret protection.
4. The **intent-detection prompt** correctly drops Akamai bot-detection
   headers (zero `EE30zvQLWf-*` headers in the generated workflow.json).
5. The **playbook compiler** produces structured locator-priority steps
   with parameter substitution and a verified extract path.
6. The **runner's screenshot-on-failure** turns each iteration cycle
   from "print and pray" to "look at the picture."
7. The **`replayBackend` field** transparently routes between API and
   browser paths in cron + MCP, no caller-side change required.
